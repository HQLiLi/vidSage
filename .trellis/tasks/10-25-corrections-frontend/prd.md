# 前端字幕纠错交互

> 父任务：`10-25-subtitle-manual-correction`。技术口径见父任务 `design.md` §6。

## Goal

把工作区里"禁用铅笔"的占位变成可用的行内编辑：原文和当前语种译文都能独立改，逐条即存，并把"译文已过时"和"纠错已失效"两种状态显式告诉用户。

## Scope

- 字幕行内编辑态（原文、译文各一个入口）。
- 保存、快捷键、失败还原。
- 译文过期即时标记、强制重翻入口。
- 失效纠错提示与一键清除。

不包含：后端接口、下载渲染。

## Requirements

1. 原文行、译文行各有独立铅笔；`isBusy` 时不显示；译文铅笔只在当前语种有译文时出现。
2. 编辑态用 textarea：失焦保存、保存按钮、Esc 放弃、Ctrl/⌘+Enter 立即保存。
3. 保存幂等：文本未变不发请求；请求进行中禁止重复提交。
4. 保存失败：还原编辑前文本并显示行内错误。
5. 改原文成功后，该行译文立即显示"原文已改，译文待更新"。
6. 存在过期译文时，"重新翻译"调用 force 接口。
7. 存在 `matched=false` 的纠错时，字幕区顶部显示"N 条纠错已失效"和一键清除。
8. 旧任务数据没有 id 时仍能正常展示与编辑（按时间戳兜底配对）。

## Acceptance Criteria

- [ ] AC1 任务结束后 hover 出现可用铅笔；运行中不出现；译文铅笔仅在有译文时出现。
- [ ] AC2 失焦保存成功；点保存按钮只产生一次写入；Esc 放弃后不写入。
- [ ] AC3 Ctrl/⌘+Enter 立即保存；保存成功后刷新页面改动仍在。
- [ ] AC4 保存失败时文本还原并出现错误提示。
- [ ] AC5 改原文后译文行立即出现"原文已改，译文待更新"；点"重新翻译"走 force 且完成后标记消失。
- [ ] AC6 A 语种纠错不影响切换到 B 语种后的显示。
- [ ] AC7 重新生成字幕后顶部出现"N 条纠错已失效"，一键清除后提示消失。
- [ ] AC8 缺 id 的旧数据可正常展示与编辑。
- [ ] AC9 `npm run type-check` 与 `npm run lint` 全绿。

## Dependencies

- 依赖 `10-25-corrections-data-api`（接口）与 `10-25-corrections-read-paths`（下载内容正确）。
