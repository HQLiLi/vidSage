## 一、改动边界

## 二、A：总结提示词的字段语义重定

`fixed` 与 `note` 的定义要重写，并删掉与「note = 替换理由」冲突的三条约束。

```
- fixed ：正确的写法，也是字幕里应当替换成的写法。
          正确写法是外语原文时直接写外语原文（如「Mittelhau」），不要退而求其次写成中文音译。
          若原文本来就写对了，与 asr 相同。
- note  ：替换理由。一句话说清 asr 这个写法是怎么错的、为什么该换成 fixed。
          必须提到 asr 与 fixed 的具体写法，但只能写成「为什么该换成 fixed」；
          不能写成「两个写法都可以」的并列口吻——纠错模型会误以为 fixed 是别名而不去替换。
```

主题的要求补一句：提到术语表里的词时用 `fixed` 写法，不要用 asr 里那个错写法。

**删**（原 `note` 段落里的三条）：`需要提外语原文时写成「德语原文 Mittelhau」这样的说明`、`不要重复 asr 或 fixed 里的写法`、`不要出现「应为」「识别错误」这类修正字眼`。

保留不变：同音误写按上下文推断、拿不准不要编、只列专有名词、最多 30 条、只输出 JSON。

## 三、B：清洗提示词的禁令收窄与判定口径

「禁止翻译」是本次故障的直接原因，必须收窄成**只对术语替换让路**，并把判定权明确交给模型。

1. 开头那句「你的唯一任务是修正字幕里的识别错误，禁止翻译、禁止改写」→ 去掉笼统的「禁止翻译」，改写为「只修正识别错误，禁止改写：不改句式、不改措辞、不合并或拆分句子」。
2. 「- 保持原语言：中文保持中文，英文保持英文，绝不翻译。」→ 前面加限定：「除术语替换外，保持原语言：……」
3. 新增「术语替换的判定」段：

```
术语参考给的是「候选正确写法 + 替换理由」，不是命令——它只说明 ASR 可能把哪个词记错了，
换不换由你按这一句的上下文判断：
- 判据：把 asr 写法换成 fixed 写法后，这句话在同一上下文里是否照样通顺、意思是否更准确。
  读得通就换。
- 读不通就保留原写法（例如术语表列的词在这一句里恰好是别的意思），
  不要为了用上术语表而硬换。
```

4. 新增正例 + 反例各一条（**放 system prompt**，属常驻判定口径，不跟每批术语表起伏）：

```
例1 术语表给了「米特号 → Mittelhau（候选正确写法）：ASR 把德语术语记成了中文音译」。
    原文「米特号是其中记载最少的一种斩击」→ 修正「Mittelhau 是其中记载最少的一种斩击」。
    换后照样通顺且更准确，所以换。
例2 术语表给了「这个展 → 这个斩」，但这句讲的是展会：
    原文「这个展办得挺热闹」→ 换成「这个斩办得挺热闹」读不通，所以保留「这个展」不动。
```

反例是**必需项**：R2 把判断权交给了模型，只给正例等于把判断权又收回去，模型会学成「一律替换」。反例选 `这个展 → 这个斩` 是因为它与本期真实术语表同源，可信度高于杜撰例子。

## 五、D：校验层的基线豁免

### 基线构造

对每个在本批被渲染进术语参考、且 `asr != fixed` 的术语，在本批原文里把 asr 字面串替换成 fixed，得到**基线**文本。匹配沿用与渲染同一套判定（小写包含），替换用字面 `String.replace`。

### 通过条件

```
max(ratio(原文, 候选), ratio(基线, 候选)) ≥ 阈值
```

**为什么取 max 而不是只跟基线比**：只跟基线比的话，模型按 R2 判断「读不通、保留音译」时，候选≈原文，而原文与基线的相似度恰恰是 0.571 / 0.684 / 0.492 < 0.7 → 会被判「改太狠」重试，等于把刚交给模型的判断权又抢回去。**原文和基线都是合法目标**，够到任一个都算过。

### 已知后果（接受）

取 max 之后，「只换了一半」也可能过校验（`乌波号 + 翁特号` 那条只换前者时，两侧相似度 0.7727 / 0.7925 都在阈值之上）。**能不能过取决于该句里术语占多大比重**：术语占比大时原文那一侧会掉到阈值下，只剩基线那一侧撑得住——单测里 14 字的那条就是如此（原文侧 0.6875 < 0.7，靠基线 0.7317 才过）。这不是漏洞，是 R2 的自然结果——判断权给了模型，机器就不该替它逐词裁。**但要靠 E 的指标把这种情况照出来**，否则就是本次静默失败重演。

> 2026-09-28 订正：本条原写「与原文、与基线的相似度都在阈值之上」，把它当成了一般结论。实算只在上面那个例子里成立，故改为按占比分情形描述。

### 签名变化

命中术语需从 `clean()` 传进 `validate()`（后者现在是包级可见、无直接单测，但签名仍要改）。基线只在 `validate()` 内部用于比对，不外泄。

## 六、E：术语替换指标

### 口径定义（写进 Javadoc，免得后来者误解）

对本批每个被渲染进术语参考、且 `asr != fixed` 的术语 t：

- 取本批原文中含 asr 的条目集合 K；
- **K 中任一条**的候选文本含 fixed → 记 t 为「已替换」，`termApplied++`；
- 否则记 t 为「未替换」，进日志清单；
- 无论哪种，`termHits++`。

两项都是**跨批次累计**，汇总进 `CleanseResult`。

这是**保守近似**：模型若把 fixed 写成变体形（如 `Mittel Hau`、`Mittelhau（米特号）`），会被算成「未替换」，日志多报一条。宁可多报让人去看一眼，不可漏报。

`asr == fixed` 的条目（如 `日耳曼剑术`）从分子分母都排除——它们本来就不需要替换。

### 落点

- 日志：每批一条 **DEBUG**（含命中/替换数与未替换清单）；汇总数（跨批累计）加进 `SubtitleCleanupService` 现有的「字幕清洗完成」那条。

  > 2026-09-28 订正：原写「级别 `info`」，与 `logging-guidelines.md` 的级别分层冲突——本类是 **Provider 内部节点**，该层规定用 DEBUG（同粒度的「字幕纠错批次」本就是 DEBUG），INFO 只留给有外部副作用的调用锚点。按规范改为 DEBUG；服务层那条汇总仍是原有级别，R8 的可观测性由「DEBUG 细粒度 + 服务层汇总 + HTTP 响应字段」三处共同承担，不依赖这一条的级别。
- 契约：`CleanseResult` 加 `termHits`、`termApplied` 两个 `int` → `CleanedSubtitle` 同步 → `CleanedSubtitleResponse` 加两个带 `@Schema` 的字段。断点复用路径（`toCleaned(existing, ..., 0, 0)`）与新增字段一起补 `0, 0`。

> **⚠️ 指标测的是「遵从术语表的程度」，不是「正确性」**——术语表本身写错时，它照样满分。2026-09-28 六次复跑实测：摘要层 5 次把 `帕姆` 写成 `Palm`（正确是 `Pommel`），产物里躺着错词，而 `termApplied` 次次满值、`retry=0`。**别拿这两个数字当作「替换都对了」的证据**；要看产物本身，或改用能暴露表内错误的观测（见 `research/term-source-limitation.md`）。

## 七、数据流（改后）

```
原始 segments
  └─ ContentSummarizer  ──→ SubtitleContext{theme(用 fixed 写法), terms[{asr, fixed, note=替换理由}]}
       └─ buildUserPrompt ──→ 术语参考段: "- "asr" → "fixed"（候选正确写法）：note"
            └─ 清洗模型 ──→ 候选
                 └─ validate: max(ratio(原文,候选), ratio(基线,候选)) ≥ 阈值
                      ├─ 过 → 采纳，且按 E 口径记 termHits/termApplied
                      └─ 不过 → 重试（原因文案不变）
```

## 八、取舍

1. **替换不做机器强制**（Q4）。本次失败证据是「模型不敢换」（三处禁令堵死），不是「模型判断不该换」。先把堵点拆掉，靠复跑验证；若复跑显示模型仍整体不换，再考虑输出契约方案。
2. **校验层取 max 而非强制基线**（Q2 + R2）。理由见第五节。
3. **不放宽 asr 命中判定**（Q7）。`密度号` 这类变体靠模型自己推断；模糊匹配最容易误伤 `第一件` 这类泛用词。
4. **正反例放 system prompt 而非用户模板**。它是常驻判定口径，不该跟每批术语表起伏；代价是 system prompt 变长几百字，每次调用都发，可接受。
5. **note 允许提 asr/fixed**（R5）。原禁令的顾虑是「怕清洗模型把 fixed 当别名」，该顾虑仍有效，改由措辞约束承担（只能写成「为什么该换成 fixed」）。

## 九、兼容性与回滚

- **兼容**：不改 API 的既有字段语义；只新增两个字段，属向后兼容扩展。`reference`（人工术语表）链路不动。
- **断点复用**：`-clean` 产物已存在时仍直接复用并返回 `0,0`，包括新的指标字段——语义与 `correctedCount` 一致（不重跑就没有本趟统计）。这正是复跑前必须删 `-clean` 的原因。
- **回滚**：提示词（A/B/C）与代码（D/E）**分两次提交**，任一不达标可单独回退。提示词回退只需 revert 文本，不影响编译。

## 十、风险

1. R3 不许点名「必须换」+ 验收要四处全中 → 成败全押在模型判断力上，可能要迭代几轮提示词。这是已拍板的路线，风险在此登记。
2. 正例用了本期真实例子，模型可能读成「这期就该这么换」而不是「这一类怎么判」；反例是主要对冲手段。
