## 源需求（范围）

1. 下载源适配器接口 + yt-dlp 命令行实现（B站 / YouTube；抖音仅留接口标记实验性，不实现）。
   - **只负责「拿到视频文件」**，不承担音频抽取（理由见 epic design.md「输入路线与外部工具」）。
   - 版本钉死；提供版本探测与新鲜度告警，**不做自动更新**。
2. 音频抽取：ffmpeg 命令行调用，**两条输入路线（URL / 本地文件）共用同一段逻辑**。
   - 输出格式随 ASR 路径：本地 FunASR → wav；云端 DashScope → m4a。
3. 字幕获取双路：
   - 优先平台已有字幕：**人工字幕优先（`--write-subs`），自动字幕兜底（`--write-auto-subs`）**。
     参考项目只实现了自动字幕，人工字幕是缺口，见 `research/oss-references.md` 第 14 条。
   - 无字幕走 ASR：`ASRProvider` 抽象（`vidsage.asr.provider` 配置切换），本地 FunASR 微服务为默认（开发/演示替身），云端 `DashScopeAsrProvider` 为兜底（已落地，提交+轮询）。
4. 阶段产物落盘、可断点复用（管线约定见 epic design.md）。
5. 任务进度接入 MVP-1 的 SSE 推送。→ **已改为延后，见「规划期决策」**
6. **外部工具可用性检查**：yt-dlp / ffmpeg / ffprobe 存在性与版本探测，缺任一即给出「缺什么、怎么补」的明确报错。

## 规划期决策（2026-09-25，用户逐条拍板）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 任务拆分 | 切成两个子任务：**2a 视频 → 音频**、**2b 音频 → 字幕** | 两段各自可独立验证：2a 的产物是音频文件，2b 的产物是 SRT。切点落在唯一的中立边界（音频文件）上，两侧契约不重叠 |
| 2 | 管线阶段顺序 | **严格线性**：download → extract audio → subtitles | 有平台字幕时也照下视频、照抽音频。换来阶段语义单一、断点复用与失败排查都简单、视频本体为阶段二「点击时间戳跳转」留用。省流量的「字幕探测前置」列为后续优化，不进本任务 |
| 3 | SSE 依赖（源需求 5） | **延后**：本任务不接 MVP-1 的 SSE | MVP-1（任务提交 / 落库 / SSE）仍在 planning、零代码，session 9 已定「MVP-2 先行」。2a/2b 只留最小的中立进度事件契约，SSE 端点等 MVP-1 落地后另立串联任务 |

**决策 2 的已知代价（显式记账，不藏）**：拆分与线性顺序导致同一 URL 被 yt-dlp 访问两次——2a 下载视频时一次，2b 用 `--skip-download --write-subs` 拉字幕时又一次。
第二次只取元数据与字幕文件（数 KB～数十 KB），不重复下载视频本体，代价可接受；换来的是 2a 不认识「字幕」这个概念、2b 不认识「ffmpeg 路径」这个概念，两侧知识点零重叠。

## 通用纪律（两个子任务都适用）

1. **索引不是规格。** `../09-24-vidsage/research/oss-references.md` 开篇自己写明：它是索引，条目里的机制描述省略了源码的边界处理与错误分支，**动手写代码前必须按条目给出的路径打开源码读原文，只读摘要等于二手转述**。
2. **许可证红线（不可绕）。** 参考项目中 **VideoCaptioner 是 GPL-3.0，一行源码都不能抄**（vidSage 大概率公开，传染会污染整个仓库）；VideoLingo（Apache-2.0）与 AI-Media2Doc（MIT）可搬运但须保留声明。而 VideoCaptioner 恰好是 MVP-2「ffmpeg 抽音频」与「平台字幕」两处的**首选参考**——凡参考它的地方，只能读懂后用自己的话重写。MVP-2 是 Java，三个参考项目全是 Python/TS，本就只能抄契约与设计。
3. **实测优先于推断。** `../09-24-vidsage/research/external-process-integration.md` 的规矩：标「未验」的都是推断，用前必须自测；结论回写该文件。

## 跨子任务验收标准（父任务负责，两个子任务都归档后逐条核）

- [ ] 一条 B站链接 + 一条 YouTube 链接，各产出字幕文件，且**平台字幕与 ASR 两条路径都被真实跑到过**。
- [ ] 一个本地 mp4 + 一个本地纯音频文件，走 ASR 路径产出字幕。
- [ ] 同一段音频在 `vidsage.asr.provider=local` 与 `=cloud` 下各跑一次，产出结构一致的 SRT。
- [ ] 中途失败后重跑，已完成阶段被跳过、不重复下载 / 抽音频 / 转写（断点复用）。
- [ ] 缺任一外部工具（yt-dlp / ffmpeg / ffprobe）时，报错说清「缺什么、怎么补」。
- [ ] B站字幕拉取的登录 / 风控边界形成实测结论，回写 epic「未决问题」。
- [ ] 全流程留至少一条真实运行证据。

## 不做（整个 MVP-2）

- ASR 模型 bake-off、说话人分离（epic 未决问题，另行决策）。
- 翻译、结构化总结（MVP-3 / MVP-4）。
- SSE 端点、任务落库、任务提交接口（MVP-1）。
- 抖音下载实现（仅留实验性接口标记）。
- 长音频静默点切分、长音频分块转写（`oss-references.md` 第 10/16/17 条；等云端或本地长音频真的踩到超时/OOM 再做）。
- ASR 内容寻址缓存（`oss-references.md` 第 18 条）：本任务只用「产物存在即跳过」的粗粒度断点，内容哈希级缓存留给重跑成本真实暴露之后。
