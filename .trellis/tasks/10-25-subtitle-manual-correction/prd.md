# 字幕手动纠错

## Goal

让用户在工作区里直接改正字幕：清洗后的原文、以及任意已翻译语种的译文，都能逐条修改；改动持久保存，不破坏机器产物的可追溯性，并让用户清楚知道改动之后哪些内容已经过时。

## 背景

- 前端目前只有一个 hover 才出现、始终 `disabled` 的铅笔按钮（`TranscriptPane.vue`），后端没有任何单条字幕的写接口。
- 旧原型 `prototype/` 里有行内编辑，但只改原文、只存在内存，没有迁移到正式前端。
- 磁盘上的 `clean-segments.json` 是页面、翻译、SRT 导出的共同来源；它会在重新生成字幕时被覆盖、机器原文不保留旧版本。
- 关键词是用户提交时手填、任务级存储，不从字幕派生，因此改字幕不影响关键词。

## Requirements

### R1 编辑范围

- 只改文本：不支持改起止时间、删条目、合并/拆分、改说话人。
- 可改对象：CLEANED 的原文；当前显示语种、且已有译文的译文。
- 仅任务结束后可编辑；有 `RUNNING` 的 run 时只读。
- ORIGINAL（ASR 原始输出）永远不可改。

### R2 编辑交互

- 原文、译文各有独立编辑入口，不合并为一次提交。
- 编辑态用 textarea；失焦即存 + 保存按钮 + Esc 放弃本次编辑 + Ctrl/⌘+Enter 立即保存。
- 保存幂等：内容未变不发请求；点保存按钮不产生第二次写。
- 保存失败：恢复编辑前内容并提示，不静默丢改动。

### R3 持久化与可追溯

- 纠错独立存储；磁盘产物（`original-*` / `clean-*` / `translated-*`）保持机器输出不变。
- 每条纠错保存"改之前的机器文本"和"用户改后的文本"。
- 删除一条纠错 = 恢复该条的机器原文/机器译文。
- 纠错按 Segment id 锚定，同一份 ORIGINAL 与切分配置下重跑后仍能对上。

### R4 下游过期

- 改原文 → 对应译文标"原文已改，译文待更新"；改译文 → 不影响其他产物。
- 过期不落库：按译文自带的 `sourceText` 与当前原文文本实时比对。
- 关键词、`context.json`、`terms.json` 不受字幕纠错影响。

### R5 重翻

- 提供"重新翻译"：强制重跑当前语种（现有翻译接口加 force 语义）。
- 重翻后保留用户手改的译文并覆盖在新机器译文之上；某条的原文也变过时标"译文待复核"。
- 不提供单条重翻。

### R6 读取口与下载

- 页面展示、下载 `segments.json` / `subtitles.srt`、重新翻译取源文本，三处都必须看到纠错后的内容。
- 没有纠错时，下载内容与磁盘文件逐字节一致。
- `?raw=1` 时永远返回磁盘机器原文件。
- ORIGINAL 全部、CLEANED 的 `context.json`、TRANSLATED 的 `terms.json` 永远返回磁盘原样。

### R7 失效纠错

- 重新生成字幕后，segment id 对不上的纠错保留在库里，不自动删除。
- 页面提示"N 条纠错已失效"，提供一键清除（不需要逐条列表）。

## 非目标

- 跨任务的全局纠错库、纠错词库提示注入。
- 单条重翻。
- 删除/合并字幕条目、编辑时间轴。
- 原文改动后自动重翻。
- 纠错的历史版本与逐次撤销。

## 任务地图

| 子任务 | 内容 | 依赖 |
|---|---|---|
| `10-25-corrections-data-api` | segment id、纠错表、领域/仓储/API | 无 |
| `10-25-corrections-read-paths` | 三个读取口套用、下载渲染、force 重翻、失效判定 | 数据层 |
| `10-25-corrections-frontend` | 行内编辑、即存与快捷键、译文过期标记、失效提示 | 数据层 + 读取口 |

父任务不写代码，负责需求、跨子任务验收与最终集成评审。

## Acceptance Criteria（父任务集成验收）

- [ ] AC1 改原文后刷新页面仍在；下载 `clean subtitles.srt` 含改动；磁盘 `clean-segments.json` 字节未变。
- [ ] AC2 改 A 语种译文不影响 B 语种；下载 A 语种 `subtitles.srt` 含改动；磁盘译文文件字节未变。
- [ ] AC3 零纠错时默认下载与磁盘文件逐字节一致；有纠错时与 `?raw=1` 不同。
- [ ] AC4 双语视图改原文后，译文行立即出现"原文已改，译文待更新"；强制重翻后手改译文仍在。
- [ ] AC5 重新生成字幕后出现"N 条纠错已失效"，一键清除后提示消失。
- [ ] AC6 任务运行中界面不可编辑，写接口返回 409。
- [ ] AC7 磁盘上缺少 id 的旧产物能正常读取、编辑，不报错。
- [ ] AC8 `?raw=1` 在有无纠错两种情况下都返回磁盘机器原文件。

## Notes

- 技术口径见 `design.md`；执行顺序与验证命令见 `implement.md`。
- 纠错的失败模式是"静默改错句子"之外的一切都要显式暴露：对不上就提示，不猜。
