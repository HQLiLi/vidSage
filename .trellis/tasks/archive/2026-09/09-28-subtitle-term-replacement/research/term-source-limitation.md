# 研究：术语来源的局限——摘要层的知识盲区不是提示词能压住的

> 2026-09-28，`09-28-subtitle-term-replacement` 验收复跑中暴露。记录全部实测证据、根因分层、以及四条候选解法各自的边界。
> 本文件是「把问题先记下来」的落点，**不是**待办清单；任何解法都要先立成独立任务再动。

## 一、现象

德语剑术视频 `BV1Tk3Q69Erd` 的跨书写系统术语替换**已按本任务目标全部生效**（改动前那一版产物里拉丁写法 0 处，改动后 9 处全中），但产物里出现一处**错替换**：

```
原字幕：…但实际上他的帕姆还是能够追过来
清洗后：…但实际上他的 Palm 还是能够追过来        ← 正确写法是 Pommel（剑柄末端配重球）
```

`Palm` 是「手掌」，与剑术无关。

## 二、根因分层

三层，**错在第二层**：

| 层 | 职责 | 本次实况 |
|---|---|---|
| ASR | 把语音转成文字 | 把 `Pommel`/`Oberhau`/`Unterhau`/`Mittelhau` 记成了中文音译（`帕姆`/`乌波号`/`翁特号`/`米特号`）——**这是所有下游问题的源头** |
| 摘要层（`ContentSummarizer`） | 读全篇，提炼主题 + 术语表（`asr`/`fixed`/`note`） | **在这里编了一个读音相近但语义错误的词**：`帕姆 → Palm` |
| 清洗层（`subtitleCleanupChatClient`） | 按术语参考替换 | 只是照做 |

**不是清洗层越界**——`帕姆` 一直在术语表里，是表本身写错了。这一点最初被误判为「清洗层改了表外的词」，靠观测日志才纠正过来。

## 三、实测证据（6 次复跑，同一份输入）

用 `SubtitleContextSummarizer` 的 DEBUG 日志抓取每次摘要层的原始输出（日志是唯一记录：`-clean` 产物会被下一次复跑覆盖）。

| 次 | 提示词版本 | `帕姆` 的 fixed | 主题写法 | termHits/termApplied | retry |
|---|---|---|---|---|---|
| run1 | 本任务第一批改动后 | **Palm** ❌ | asr 写法 | 5 / 5 | 0 |
| run2 | 同上 | Pommel ✅ | fixed 写法 | 5 / 5 | 0 |
| run3 | 同上 | **Palm** ❌ | fixed 写法 | 5 / 5 | 0 |
| run4 | 再加「不许凭读音拼」+ 反例 | **Palm** ❌ | fixed 写法 | 5 / 5 | 0 |
| run5 | 同上 | **Palm** ❌ | fixed 写法 | 8 / 8 | 0 |
| run6 | 同上 | **Palm** ❌ | fixed 写法 | 5 / 5 | 0 |

结论：

1. **`Palm` 5/6**。加了「外语原文只能凭领域知识确定、绝不能凭读音拼一个出来」+ 反例（点名「帕姆 读音像 Palm 但不是它」）之后，**3/3 仍然错**。措辞压不住先验。
2. **模型不觉得自己在猜**。run4 的 note 原文：「字幕将剑术术语 **Palm** 音译误写为「帕姆」，应替换为原文 Palm。」——把 Palm 当剑术术语来断言。一个自信的模型不会去查证，也不会标记「不确定」。
3. **它知道 Palm 不是德语**：其余 4 条的 note 都写「应替换为**德语**原文」，只有这条写「应替换为原文」。即语种判断没出错，是**把词认错了**。
4. **指标全程绿灯**：6 次的 `termApplied` 都是满值、`retry=0`，而产物里躺着错词。**指标测的是「遵从术语表」的程度，不是正确性**——「表写 Palm、输出 Palm」对指标来说就是「已替换」。
5. **摘要层每次输出的表都不一样**。同一份字幕、同一版提示词：`第一件` 在改动后 6 次里只出现 1 次（run5，那次的表有 8 条，含 `第一件`/`做个展`/`这个展`）；主题写法 6 次里 1 次（run1）仍用 asr 写法。→ **任何「一次定稿」的设计都建立在不稳定的地基上**。

## 四、候选解法与各自边界

### 1. 换更好的 ASR 模型（项目所有者判断：治本方向）

**为什么这是治本**：所有下游问题都源自 ASR 把拉丁/德语术语记成了中文音译。ASR 若能把 `Oberhau`/`Mittelhau`/`Pommel` 直接转成拉丁原文，摘要层就没有「猜原文」这件事可做，`Palm` 这类幻觉从源头消失。

- 现状：`DashScopeAsrProvider`（阿里云）/ 本地 whisper 两条路，`SubtitleRoute` 可选。词表/热词能力是这条路的抓手（向 ASR 传术语白名单，比事后纠正可靠）。
- 代价：换模型要重新评估成本、延迟、整体准确率；且**只能减少不能消除**（冷僻词照样可能错）。
- **定位：LLM 清洗只是 ASR 产出的改善层，不是纠错层。**

### 2. `reference`（人工术语表，HTTP 查询参数）——现在等于不可用

`POST /api/subtitles/clean` 有 `reference` 查询参数，纯文本原样拼进提示词末尾。但：

- **事后不生效**：`SubtitleCleanupService.java:110-115` 只要 `-clean` 产物在就直接返回缓存，`reference` 连读都没读；全仓无 force / 覆盖 / 重跑开关。→ 「用户看到 `Palm`、补一笔 reference 重跑」**物理上不通**。
- **用户不知道要传什么**：要求调用者在第一次跑之前就知道 `帕姆` 对应 `Pommel`，等于要求他先懂这个领域。

### 3. 术语表可见 → 可改 → 可重跑（把定义权交给用户）

合理性：**喂给本项目的视频，作者本人通常就是领域内的人**——他讲剑术，他知道 Pommel 怎么拼。

- 第一层（便宜）：术语表落成可见产物（如 `terms-<route>.json`）或进 HTTP 响应。本任务已加 DEBUG 日志（`SubtitleContextSummarizer`），那是开发者视角；产品化未做。
- 第二层：改 `reference` 语义 + 显式重跑开关 + 前端编辑入口。动了 API 契约与断点复用语义，属独立交付物。
- **不需要让模型标注「不确定」**（它并不觉得自己不确定，见证据 2）。让用户扫一眼整张表就够——`帕姆 → Palm` 摆在表里，懂行的人一眼看出问题。

### 4. 联网搜索工具

**能**：把「凭记忆猜」换成「查证」。搜「HEMA pommel 剑柄配重球」大概率直接命中。

**关键限制：它可能一次都不触发。** 工具由模型自主决定调不调，而模型不觉得自己在猜（证据 2）。不配强制流程，最可能的结果是照样直接吐 `Palm`、一次搜索都不发起。要生效必须硬约束：**凡是要写外语原文的条目，先用搜索查证；查不到就把 `fixed` 留空或不列这一条**。

其余成本与边界：

- 项目**零 LLM 工具调用基础**（`@Tool`/`ToolCallback`/`FunctionCallback` 全仓零命中；`provider/tool/` 里的 `ExternalProcessRunner` 是外部进程执行器，**不是** LLM 工具）；`pom.xml` 无任何搜索 SDK；`docs/` 与主 PRD 从未提过工具调用 → 从零引一条链路（新依赖 + key + 配额）。
- `summarize()` 现在是一次 `.entity()` 成型、失败降级空上下文；加工具后内部变成多轮工具循环，延迟上升、失败面变大（工具超时、迭代上限、搜索结果污染提示词）。好在**降级设计已经在了**，摘要失败不致命。
- 查不到（冷僻/自制叫法）仍要弃权 → 仍需人工兜底。**它减少错误，不消除错误。**
- **建议先做 spike**：拿这条视频的原始字幕，套上搜索工具跑一次摘要，看 `帕姆` 是否变成 `Pommel`、以及是否真的发起了搜索。不做 spike 直接上，很可能引一条永不触发的链路。

### 5. 项目维护领域术语库

摘要层只能从库里**选**已写好的原文，不许自由生成。彻底消灭「编一个读音像的词」，但要建库、要覆盖领域，属长期投入。可作为第 3 条的加强版（库优先、用户兜底）。

### 已排除

- **从视频元数据里挖原文**：查过 `source.info.json`，标题无、简介长度 1（空）、标签只有中文加 `HEMA`。方向本身没错（爱写术语的简介会有用），但不能当主路。
- **让清洗层否决拉丁化新词**：清洗层同样没有领域知识，大概率照样照做。

## 五、给后续任务的输入

1. **优先级**（项目所有者 2026-09-28 判断）：换更好的 ASR 模型是治本方向；LLM 清洗只做改善。
2. 若要动第 3 条（可见可改可重跑），它跨 API 契约 + 断点复用语义 + 可能的前端，**必须先立独立任务**。
3. 第 4 条（联网搜索）排在「术语表可见」之后：不先让表可见，连「搜索帮上了多少」都看不见、验收不了。
4. 本任务的验收里 `帕姆 → Pommel` 一行已降级为**已知限制**，见 `prd.md`；`第一件 → 第一剑` 降级为**不稳定项**（6 次里 1 次）。
