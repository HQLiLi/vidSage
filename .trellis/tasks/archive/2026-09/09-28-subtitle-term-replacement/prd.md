# 字幕术语替换：提示词与校验层改造

## Goal

让 ASR 音译的专有名词（米特号/乌波号/翁特号/帕姆）在字幕正文里替换成正确写法（Mittelhau/Oberhau/Unterhau/Pommel）：改总结提示词的 fixed/note 语义、清洗提示词的翻译禁令边界与判定示例，校验层加基线豁免与术语替换指标。

## 背景

2026-09-28 复跑德语剑术视频（BV1Tk3Q69Erd）发现：总结阶段正确提取了术语，但清洗阶段只改了**同书写系统**的条目，四条跨书写系统的（`乌波号/翁特号/米特号/帕姆`）一条没改。

| 术语 | asr → fixed | 实际 |
|---|---|---|
| 乌波号 → Oberhau / 翁特号 → Unterhau / 米特号 → Mittelhau / 帕姆 → Pommel | 汉字 → 拉丁 | ❌ 全未替换 |
| 第一件 → 第一剑 / 这个展 → 这个斩 / 密度号 → 米特号 | 汉字 → 汉字 | ✅ 已替换 |

规律 100% 对齐「是否跨书写系统」，与主题是否含错写法无关（`乌波号/翁特号/帕姆` 都不在主题里，一样没改）。根因两处，各有实测证据：

1. **提示词自相冲突**：清洗提示词里三处「禁止翻译 / 保持原语言」（`ChatClientConfig` 的 system prompt 两处、`SubtitleCleanser` 用户模板一处）与术语表的要求直接撞车，而术语表只有一句「用其中术语纠正误识别的专业名词」，从未说明「跨书写系统的替换不算翻译」。模型选了更硬的那条禁令。
2. **校验层会反杀**：`validate()` 的相似度守卫（长句底线 0.7）会把**正确的**术语替换判成「改太狠」。按 `TextSimilarity` 的 LCS 实现在真实文本上实测：

   | 条目 | 替换到位后相似度 | 底线 |
   |---|---|---|
   | 乌波号+翁特号 | 0.571 | 0.7 |
   | 米特号 | 0.684 | 0.7 |
   | 三种斩击那句 | 0.492 | 0.7 |

   即：只改提示词的话，模型一旦真去替换就会连吃 3 轮重试，`agentLoop` 用尽后**整批回退原文**——连原本改对的那几条也一起丢，结果比现状更差。

## Requirements

- **R1** 字幕正文里，ASR 把外语专有名词记成中文音译时，要替换成正确写法（本期即拉丁原文）。
- **R2** 替换与否由清洗模型按上下文语义自行判断：换成候选写法后句子在同一上下文里照样通顺、语义更准则换；读不通则保留原写法。机器侧不做强制。
- **R3** 判断依据只能是「术语表 + 提示词里的判定口径与示例」；**提示词里不得点名哪些词必须换**。
- **R4** 术语表未命中的其他专有名词仍一律不动。
- **R5** 术语的 `note` 字段语义改为**替换理由**（说清 asr 错在哪、为什么该换成 fixed）。
- **R6** 主题（`theme`）里提到术语时用 `fixed` 写法，不用 asr 写法。
- **R7** 校验层新增基线豁免：不得因术语替换本身触发「改太狠」重试。
- **R8** 新增术语替换的可观测指标（命中数 / 已替换数 / 未替换清单），进日志与 HTTP 响应。
- **R9** 既有行为不得回退：`第一件→第一剑`、`这个展→这个斩`、`密度号→米特号` 仍要改对；最小改动、条号不变、去口头语、跨批历史与后窗机制照旧。

## 非目标

- 不放宽 asr 命中判定去兜住 `密度号` 这类**未命中术语表**的变体——它靠模型自己按上下文推断（2026-09-28 决策）。模糊匹配最容易误伤 `第一件` 这类泛用词，风险大于收益。
- 不加「模型须为每次保留显式声明理由」的输出契约（即不改 `{"2": {"text": ..., "keep": [...]}}` 这类结构）。
- 不以机器门槛校验术语表的正确性；幻觉风险仍由总结提示词自身的「拿不准不要编」约束承担。

## Notes

- **术语来源的局限（摘要层知识盲区、`reference` 事后不生效、四条候选解法）单独记在 `research/term-source-limitation.md`**——项目所有者 2026-09-28 判断：LLM 清洗只是 ASR 产出的改善层，真正减少这类错误治本的方向是换更好的 ASR 模型。
- 复跑前**必须先删掉工作目录下两个 `-clean` 产物**，否则 `readCheckpoint` 命中断点会直接复用、根本不调 LLM（实测 `correctedCount=0, retrySteps=0`）。
- 本任务没有可入库的测试 fixture（`backend/data/` 已 gitignore，`src/test/resources` 无字幕样例），验收只能靠本机那条真实视频复跑。
