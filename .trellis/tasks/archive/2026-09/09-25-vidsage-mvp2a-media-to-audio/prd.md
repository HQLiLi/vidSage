# MVP-2a 输入获取与音频抽取 — PRD

> 父任务（源需求与规划期决策）：`../09-24-vidsage-mvp2-subtitles/prd.md`。
> 技术方案：`design.md`；执行计划：`implement.md`。
> 必读研究：`../09-24-vidsage/research/external-process-integration.md`（**实测坑，最重要**）、`../09-24-vidsage/research/oss-references.md` 第三节 MVP2 小节（第 15 条 ffmpeg 抽音频、第 14 条 note）。

## 目标

把「一个 URL 或一个本地媒体文件」变成「一个符合调用方指定规格的音频文件」，并把过程中所有外部程序调用收敛到**唯一一个进程执行器**里，供 2b 与后续阶段复用。

一句话判据：**2a 交付的是一个能拿音频的接口，而不是一段能跑通的脚本。**

## 范围

### 1. 外部进程执行器（本任务的地基）

yt-dlp 与 ffmpeg **共用同一个执行器**，它负责：

- 参数以 `List<String>` 传递，**绝不拼字符串走 shell**（编码与注入双重风险）
- 并发读尽 stdout 与 stderr（防管道缓冲区写满导致双向死锁）
- 超时可控，超时后强制结束进程并回收，结果里标记「超时」
- 子进程输出**按 `native.encoding` 解码**，取不到时兜底 UTF-8（本机 yt-dlp 吐 GBK，用默认字符集读会静默乱码——见研究笔记第一节）
- 返回「退出码 + stdout + stderr + 实际命令行 + 是否超时」，**不因非零退出码抛异常**（退出码语义极弱，分类交给调用方，见研究笔记第二节）

### 2. 外部工具诊断

- 探测 yt-dlp / ffmpeg / ffprobe 的**存在性、解析到的绝对路径、版本**；yt-dlp 额外给出**新鲜度**（版本号是 `YYYY.MM.DD` 日期式，算距今多少天，超阈值告警，**不自动更新**）
- 缺任一工具时，报错必须给出「**缺什么 + 怎么补**」（可复制粘贴的安装/配置指引）
- ffmpeg 路径**一处配置、两处使用**：Java 抽音频与 yt-dlp 的 `--ffmpeg-location` 读同一个配置项
- 诊断结果通过一个只读接口暴露（epic design.md 已明确要「诊断端点报新鲜度」）

### 3. 输入获取（两条路线）

- `MediaAcquirer` 适配器接口 + 两个实现：
  - **yt-dlp 实现（URL 路线）**：钉死版本（不自动更新）；落 `--write-info-json` 元数据（标题、时长、后续字幕清单的来源）；下载产物落进任务工作目录
  - **本地文件实现（本地路线）**：存在性 / 可读 / 是否媒体文件的前置校验，直接采用不拷贝
- **抖音**：只留实验性标记，不实现
- 输入用 sealed 类型表达（`RemoteUrl` / `LocalPath`），两条路线对上层是同一个契约

### 4. 音频抽取（两条路线共用同一段逻辑）

- ffmpeg 命令行调用，输出规格由**调用方传入** `AudioSpec`
- 预置两种规格：**WAV（PCM 16k 单声道，给本地 FunASR）** 与 **M4A（AAC 16k 单声道 48kbps，给云端 DashScope）**
- **显式选音频轨**（`-map 0:a:<n>`，默认第 0 条）：B站视频常有多音轨，不依赖 ffmpeg 的默认流选择，避免静默取错轨
- **2a 不认识 ASR**：不读 `vidsage.asr.*`，不做「要 wav 还是 m4a」的判断——那是 2b 的职责（2b 让 ASR provider 声明规格，再把规格传进来）
- 成功后校验产物存在且非空；失败时抛异常并附 **ffmpeg stderr 的关键片段（尾部行）**——完整 stderr 留在 `ProcessOutcome` 与 DEBUG 日志里供深挖，**不塞进面向用户的错误消息**（原写「完整 stderr」会输出上百行输入流转储，与错误消息该有的可操作性冲突）

### 5. 阶段产物落盘 + 断点复用

- 工作目录按**输入内容寻址**（规范化输入串 + 规格的哈希），同一输入重跑落回同一目录
- 每阶段产物落盘；**产物已存在且非空即跳过该阶段**，并在结果为「跳过」时给出可观测的标记
- 中途失败后重跑，不重复下载 / 抽音频

### 6. 最小的进度事件契约

- 一个中立的阶段事件 record + 一个回调接口，阶段服务在开始 / 成功 / 跳过 / 失败时各发一次
- **刻意保持最小**（阶段名 + 进度 + 消息 + 状态），形状参考 `oss-references.md` 第 2 条的 `{progress, stage, message, state}`；**真实形状应由 MVP-1 的 SSE payload 定锤**，本任务的版本是过渡态，改动预期内

## 不做

- **字幕与 ASR**（平台字幕拉取、`ASRProvider` 调用、SRT 产出）→ 2b
- **SSE 端点、任务提交、落库** → MVP-1（父任务决策 3）
- 抖音下载实现
- 长音频切分 / 分块 / 内容寻址缓存（父任务「不做」清单）
- 下载进度解析（yt-dlp 的百分比进度）：没有消费方，等 SSE 串联时再做
- 音频规格之外的转码能力（不承诺截图、切片、格式转换）

## 验收标准

> 证据分两级标注：**〔实测〕**＝真实运行（真实链接/真实文件/真实 HTTP，原始输出见 `implement.md` 步骤 9 记录）；**〔单测〕**＝单元测试覆盖，未在真实环境触发过。

- [x] 一条 B站链接 → 下载出视频文件 + info json 元数据，且**中文标题不乱码**〔实测〕
      —— 下载与 info json 见 implement.md §步骤 9-2；标题非乱码见步骤 5 证据（`title=科普知识`，4 码点 / 12 UTF-8 字节）
- [ ] 一条 YouTube 链接 → **未通过：实测阻塞**〔实测〕
      —— 无 JS 运行时的 YouTube 提取已被官方弃用，且被 bot 检测拦下（`Sign in to confirm you're not a bot`），需 cookies。**属平台侧问题，非本实现缺陷**；是否读浏览器 cookies 属隐私决策，待项目所有者定（研究笔记 §8.1 有原始输出）
- [x] 一个本地 mp4 → 不下载、直接抽音频〔实测〕（implement.md §步骤 9-4）
- [x] 同一段视频分别抽 WAV 与 M4A，两种规格都能指定并产出正确编码的产物〔实测〕
      —— wav 1527022 B 与「47.7s × 16kHz × 2B」自洽；m4a 304884 B 约为 wav 的 1/5，与选型依据吻合
- [x] 多音轨媒体能指定取哪条音频轨（默认第 0 条），`-map 0:a:0` 显式出现在生成的命令里〔单测 + 合成文件实测〕
      —— **但真实 B站 素材只有 1 条音轨**，多音轨是在 lavfi 合成文件（第 2 轨标 `default`）上验证的；真实站点的多轨源未遇到
- [x] 外部工具缺失时的报错说清「缺什么、怎么补」〔实测〕；yt-dlp 过期时给出新鲜度告警〔单测〕
- [x] 同一输入重跑，已存在的产物被跳过（断点复用），不重复下载/抽音频〔实测〕
      —— 同请求重放 9.95s → 0.0096s，日志两阶段 `SKIPPED`
- [x] 抽音频中途失败或超时后，工作目录里**不残留可被误当作成品的半截文件**〔单测〕
      —— 原子落盘（`.part` + `ATOMIC_MOVE`）与失败清理有测试；**未真实中断一次抽取来验证**
- [x] 单元测试覆盖参数拼装、编码解码、超时、退出码失败路径；**不起 Spring 容器**（159 项全绿）
- [ ] **进程超时能被打断并回收，不挂死**〔单测〕
      —— 有界 drain（`future.get(graceMs)`）有确定性单测；但**真实的 yt-dlp→ffmpeg 超时路径未触发过**（设计 §十 第 5 项仍挂着「会不会留残留进程」）
- [x] 至少一条真实运行证据（真实链接 + 真实本地文件）〔实测〕
