[2] 索引 / 约束名符合 N4  —— PASS
design §2 期望：pk_ ×6、uk_ ×9、idx_ ×1，一律带表名段。
information_schema.STATISTICS（非 PRIMARY）实测 10 条：
  intermediate_file  uk_intermediate_file_task_id_file_name                        UNIQUE
  subtitle_artifact  idx_subtitle_artifact_derived_from_run_id                     INDEX
  subtitle_artifact  uk_subtitle_artifact_task_id_artifact_type_lang_active_flag   UNIQUE
  subtitle_artifact  uk_subtitle_artifact_task_id_artifact_type_revision_lang      UNIQUE
  subtitle_keyword   uk_subtitle_keyword_task_id                                   UNIQUE
  subtitle_task      uk_subtitle_task_task_no                                      UNIQUE
  subtitle_task      uk_subtitle_task_workspace_id                                 UNIQUE
  task_run           uk_task_run_task_id_active_flag                               UNIQUE
  task_run           uk_task_run_task_id_run_no                                    UNIQUE
  workspace          uk_workspace_source_type_source_key                           UNIQUE
=> uk_ 恰 9 条、idx_ 恰 1 条，全部带表名段，无 uq_ 前缀残留。

  主键与唯一约束的**源码写法**（schema.sql 原文，非 SHOW CREATE TABLE）：
    CONSTRAINT pk_<表名> PRIMARY KEY (id)
    CONSTRAINT uk_<表名>_<列...> UNIQUE (...)
  符合 N4「主键具名 / 唯一约束用 CONSTRAINT ... UNIQUE，不用 UNIQUE KEY」。
  ★ 注意：SHOW CREATE TABLE 会把两者归一显示成 `PRIMARY KEY` / `UNIQUE KEY`，
    这是 MySQL 的规范化行为（PK 的约束名在 MySQL 里恒为 PRIMARY，写了也被忽略），
    不是偏差。判据只能看 schema.sql 原文。

[5] schema.sql 头部写明存量迁移步骤  —— PASS
backend/src/main/resources/schema.sql 第 1–8 行头部注释写明两条手工迁移：
  DROP TABLE IF EXISTS subtitle_keyword;   -- 锚点列 workspace_key 改成 task_id，并净增 updated_at
  DROP TABLE IF EXISTS task;               -- 旧任务表整块退场
理由也写了：CREATE TABLE IF NOT EXISTS 不改已存在的表，MySQL 8 没有 DROP COLUMN IF EXISTS。
