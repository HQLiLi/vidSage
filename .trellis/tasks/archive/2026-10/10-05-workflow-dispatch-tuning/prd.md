# 派发工作流提速与可观测性

## Goal

把 Trellis 子代理派发协议按 `10-03-vidsage-fe-v0` 的实测数据调优：**典型任务墙钟省 35–40%、质量路径不变**。
改动为协议文档（workflow + 技能文件），不涉及业务代码与宿主程序。

## Background（会话实测证据，数据源 `.trellis/tasks/10-03-vidsage-fe-v0/research/execution-log.md`）

- 六个派发表观生成速率全落在 10–40 tok/s，墙钟 ≈ 184k 输出 token ÷ ~30 tok/s ≈ 105 min，与实测吻合
  → 执行是**生成受限**；读写文件、构建、前缀重发均为零头。
- 上下文无忧：子代理模型窗口 1M，最肥派发（全量检查，97 次调用）峰值估计仅 ~110–155k（≤15%），
  九个代理 cacheWrite 全程为 0（前缀从未重写）→ 零压缩，安全边际 5–10 倍。优化动机是成本与墙钟，
  不是压缩风险。
- 杠杆实测预期：批次并行 ~17min、检查拆面并行 ~13min、档位分层 ~5–10min、减轮数 15–25%。
- **成本对账（2026-10-05 用户问）**：省 token 的是 R2（检查读面 −30~40%）、R4（轮数 × 前缀双砍，
  input −20~30%）、R3（机械批次生成 −30~50%）、R1 批次规模上限（摊薄固定上下文）；**并行与
  worktree 不省 token 反微涨**（固定上下文 × N + 仪式），买到的是墙钟。合计预期总量 ~14.2M →
  ~9–10M（−30%），墙钟 −35~40%；数值为估算，由 R6 台账在下次任务对照验证。
- 约束：`metadata.json` 由宿主（ZCode CLI）产出，仓库侧不可改其字段；台账只能固化宿主已报告的
  usage 三件套（subagent_tokens / tool_uses / duration_ms）。

## Requirements

- **R1 批次并行（默认协议）**：正典写明（workflow.md 注入块放英文简版镜像，D6）——规划期按依赖图给批次分层，
  **同层无关联批次并行派发、跨层串行**；准入条件 = 依赖分层清晰 + 每批文件所有权清单必填。
  **批次规模上限：单个实现派发覆盖 implement.md 步骤 ≤3–4 步**——摊薄每批固定上下文
  （规范 + 工件 ≈ 15–20k），防单批轮数失控（对照本次最肥批次 81/97 次调用）。
- **R2 检查拆面**：全量检查默认拆为**读面并行**（规范关 / 契约关 / 逻辑关，纯读不跑命令，
  无需隔离），各面读取面限 `git diff` 变更清单 + 引用锚点，禁止全量读仓库；命令关
  （type-check / lint / build）单独一个代理或主线执行，避免并发 npm 命令在
  node_modules/.tmp 上竞态。
- **R3 档位分层（协议/适配两层，2026-10-05 用户定调：机制工具私有，禁止写死）**：
  **协议层**（工具中立，入 workflow.md）：三问二值判据——① 有设计成分吗（新抽象/契约/取舍）？
  ② 错了有兜底吗（检查与合并裁决自身无兜底）？③ 能写成无歧义清单吗（清单须已由高档产出）？
  按题极性定向：①「是」（有设计）∨ ②「否」（无兜底）∨ ③「否」（不能成清单）——任一指向高档 →
  **高档执行者**；三问全指向低档（①「否」∧②「是」∧③「是」）→ **低档执行者**（一个角色名，不绑定
  工具机制）；拿不准 → 高档；低档批次遇清单外情况必须停下上报主线，禁止就地降质决策。
  **适配层**（正典 `dispatch-protocol.md` 的适配表节，中文）：每工具一行，映射「低档执行者
  → 本工具机制」+ 能力等级 + 生效验证步骤。已判明：Codex = toml `model_reasoning_effort`
  （原生）；ZCode = `.codex/agents/trellis-mechanic.toml`（Codex 格式键，**honor 与否待实测**）；
  Claude Code = 待调研补齐。**降级规则**：工具不支持按类型设档 → 全高档 + 台账记录，
  提速只取并行/减轮数收益，协议不因工具能力缺失失效。当前工具（ZCode）落地时新增
  mechanic 代理类型并实测生效（机械批次对照表观速率/思考时长）。
- **R4 减轮数与省前缀**：派发词硬规则三条款——「读齐再动手：动手前并行读取所需文件，禁止一回合
  单动作串行磨」；「验证链每批一轮：批次收尾并行跑 type-check + lint，build 留任务收尾一次」；
  「定位式读取优先：先 grep 定位再按 offset/limit 读片段，同一文件不整读两遍，禁止为确认而重读
  大文件」——累计 token ≈ 轮数 × 前缀，前两项砍轮数、本项砍单轮前缀体积。
- **R5 worktree 并行仪式与合并规程**：并行实现批次**默认各开 git worktree**（2026-10-05
  用户提议并采纳；动机 = 验证隔离 + 杜绝静默覆盖，全项目 type-check 会撞见兄弟批次半成品）。
  仪式：上游批次先 commit（新增「批次完成即 commit」约定，worktree 需已提交基座）→
  `git worktree add` 每批一棵 → 各自 `npm ci`（缓存热 ~1–2min；**禁止 node_modules 软链共享**，
  tsBuildInfoFile 竞态）→ 派发词指明 worktree 路径 → 各批独立写码 + 独立全量验证 →
  主线 `git merge --no-ff` → 删树 → 主线收尾验证。派发词必含「允许创建/修改清单 + 禁建清单
  （上游已有符号及其 import 路径）」；规划期把两批都需要的共享物上提到共同上游批次；
  真冲突合并 SOP 四步（定权威取并集 → 归一 import → type-check 找断点 → 删重复一轮验证）。
  例外：纯读的并行检查面与不跑验证的纯写入小批用同目录。
- **R6 执行台账固化**：execution-log.md 的必填列成文（派发/子代理/覆盖步骤/起止 epoch/耗时/
  usage 三件套），派发结束即记，作为后续调优的数据基线。

## Key Decisions

| # | 决策 | 依据 |
|---|---|---|
| D1 | 「同层批次并行」为**默认协议**，规划期依赖图 + 文件所有权清单做准入 | 2026-10-05 用户定调；串行默认让多数任务白丢 30–40% 墙钟 |
| D2 | 并行实现批次**默认 worktree 隔离**（2026-10-05 用户提议，讨论后采纳）；纯读检查面与免验证小批同目录 | 验证隔离（全项目 type-check 会撞兄弟批次半成品）+ 杜绝同名文件静默覆盖；仪式成本 ~4–6min 远小于并行收益 |
| D3 | 撞车合并**默认主线（代理）自主执行**，按 SOP 处理机械冲突（重复定义取并集、import 归一、
      格式差异）；冲突上升到**语义级**（两批对同一职责给出不同字段设计/不同行为——机械规则定不了
      对错）时**升级用户裁决**，呈两版本对照 + 推荐；合并后验证不过且修不动同样上报。
      规模超预期（>3 文件）可转派低档修复代理执行 SOP，裁决权不变 | 机械冲突可逆且在任务范围内，
      代理自主处理（用户不动手）；语义对错是设计决策，属用户所有 |
| D4 | 落点：**正典** `.trellis/spec/guides/dispatch-protocol.md`（新文件，中文，含协议细则 + 工具适配表）；**镜像** `workflow.md` 注入块 + 两个 SKILL.md（英文简版 + 指针）；tools/ worktree 仪式脚本；`.codex/agents/trellis-mechanic.toml`（ZCode 适配条目的落地物，生效需实测） | 档位机制工具私有，协议只写意图与判据；归属与语言见 D6 |
| D5 | 峰值上下文可观测性依赖宿主字段，本轮只固化现有 usage 三件套的台账格式 | metadata.json 为宿主产出，仓库侧不可写 |
| D6 | **语言约定（沿用 git-workflow.md 先例）**：协议正典全中文，落 `.trellis/spec/guides/dispatch-protocol.md`（协议细则 + 工具适配表合一）；`workflow.md` 注入块与两个 SKILL.md 只放**英文简版镜像 + 指针**，带 SYNC MARKER 同步义务（改正典必同步镜像，冲突以正典为准）；脚本注释中文。理由：workflow.md / 技能体是 Trellis 模板管理面（`trellis update` 块级替换），中文细节放那里会被刷新；spec/guides 是用户所有目录，且与仓库既有语言约定一致 | 2026-10-05 用户提问触发；git-workflow.md 头部已确立同一模式（中文正典 + 英文镜像 + SYNC MARKER） |
