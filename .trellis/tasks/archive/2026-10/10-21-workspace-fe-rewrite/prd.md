# 工作区页前端重写：按新原型接当前后端契约

> 父任务：`10-21-workspace-page-revamp`。
> 本文件是**父任务**：只持有源需求集、任务地图与跨子任务验收，不含实现工作，不 `start`。
> 子任务：`10-22-workspace-ready-page`（B1）、`10-22-workspace-run-page`（B2）。

## Goal

按原型验证通过的新布局**重写** `frontend/` 的工作区页，并把它接回当前后端契约——
前端自 2026-10-13 起未改动，后端字幕模型重构把契约整层换掉了，现在对任何任务都跑不通。

所有者裁定：**可以无视旧组件与旧对象，重写完成后把它们收掉**。所以这是重建，不是打补丁。

## 依赖

**依赖 `10-21-workspace-prototype` 的完整原型验证通过**（原型已验证：`npm run type-check` 与 `npm run build` 均过，
就绪态 / 关键词 / 主题 / 字幕搜索与行级编辑 / 语种选择与互换 / 本地模拟翻译 / 进度演示均已跑通）。
`prototype/` 被 `.gitignore` 排除，没有可审查的 diff，**B 必须重写，不要搬运原型代码**。

## Requirements

- **R1 布局按原型重写**：工作区页就绪态按原型的最终形态重建
  （左列三块：播放器 / 关键词 / 主题；右侧字幕区）。字幕条目 hover / 聚焦时显示修改图标，支持单条原文人工修正。
  任何有意偏离都要写进子任务的 `implement.md` 并说明理由。
- **R2 首页布局不动**，但其提交逻辑必须接回新契约。
- **R3 接回当前契约**，逐条（编号沿用 `10-21-workspace-page-revamp` 的 `prd.md` §1 表格）：

  | # | 要改成 |
  |---|---|
  | 1 | SSE 订 `GET /api/tasks/{taskNo}/runs/{runNo}/events`，模型改为 **run-scoped**（一条 run 一条流）；已终态的 run 返回 **204**，须先读快照判断再决定订不订 |
  | 2 | `TaskView` 改为 `TaskResponse`（`lastRun` 嵌套）；扁平五字段与 `artifacts` 全部改从新位置取 |
  | 3 | 四个触发点（提交 / 上传 / 翻译 / 重生成）按 `{taskNo, runNo}` 处理 |
  | 4 | `translate` 带 `{sourceLanguage, targetLanguage}` body |
  | 5 | 产物清单走 `GET /{taskNo}/artifacts`，下载走 `/{taskNo}/artifacts/{type}/{file}` |
  | 6 | 媒体播放源：**后端当前无端点**（见父任务 Q4）。前端按"无源"降级处理，不留死链 |

- **R4 关键词与主题用真实接口**：
  - 关键词：`GET /{taskNo}/keywords` 读、`POST /{taskNo}/subtitles/regenerate` 写（注意 `null` 与 `[]` 语义不同）
  - 主题：`GET /{taskNo}/artifacts/CLEANED/context.json` 读 `theme`；首版直接使用后端现有一两句话，处理 `degraded: true`
  - **修改字幕**：后端未实现；按原型实现字幕行 hover 修改图标与单条行级编辑，保存动作必须明确标注不能持久化，不假装成功。
- **R5 旧物收掉**：旧契约类型（扁平 `TaskView`）、旧 SSE 订阅路径、旧产物取值方式、被替换的旧组件，
  重写后一律删除，不留双份。
- **R6 规范**：遵循 `.trellis/spec/frontend/` 全部规范（目录结构、组件、状态、类型、样式、动画、API、质量）。

## 任务地图

R1–R6 拆成两个可独立验收的子任务。切面是**读已完成的任务**与**跑进行中的任务**——
前者不碰 SSE，后者不碰字幕渲染，两块各自都能单独端到端验收。

| 子任务 | 交付物 | 覆盖 |
|---|---|---|
| `10-22-workspace-ready-page` | 契约层（types / enums / api / utils）+ 已完成任务的工作区页 + 首页提交接线 + 旧物删除 | R1、R2、R3-2/3/4/5、R4-关键词读取与主题、R5、R6 |
| `10-22-workspace-run-page` | run-scoped SSE + 进度 + 重生成 + 翻译 + 失败/重连 + 残留清理 + 规范订正 | R1-进度形态、R3-1/6、R4-关键词写入、AC7/AC8 复验 |

**顺序**：B2 依赖 B1（B2 在 B1 重建的 store 与组件上做增量，不重建契约层）。
B1 交付后的中间态是"能打开任何已完成任务、能提交新任务并跳过去，但新任务只显示'执行中，请稍后刷新'"。

**为什么首页提交接线归 B1**：B1 一删 `TaskView`，上传页就编译不过，接线绕不开。
同理，R3 的六处里 B1 覆盖第 2、3、4、5 处（读契约与触发响应形状），B2 覆盖第 1、6 处。

## Cross-child Acceptance Criteria

- [ ] **AC1** 布局与原型一致；任何有意偏离都在对应子任务的 `implement.md` 里写明理由。
