3. ★ 发现 F1：翻译侧 LLM 全不可用时「静默交付未翻译内容」
================================================================

【怎么发现的】
  为造一个同 task 的真失败，把服务以
    -Dspring-boot.run.arguments=--spring.ai.deepseek.base-url=http://127.0.0.1:9/
  重启（LLM 指向死地址，连接必被拒），然后在 task 1 上触发一个**没翻过**的语种 zh-Hant。

【现象】
  run 6（TRANSLATE → zh-Hant）**SUCCEEDED**，artifact id=6 **READY**，error_message 为 NULL。
  但产物内容与简体源文**逐字节相同**：
    $ diff clean-subtitles.srt translated-subtitles-zh-hant.srt
    (无输出)
  两次产物字节数都是 3024。

【日志里的真相】
  DEBUG LlmSubtitleTranslator : 字幕翻译批次重试用尽，整批回退原文: 序号=1, 句数=12
  DEBUG LlmSubtitleTranslator : 字幕翻译批次重试用尽，整批回退原文: 序号=2, 句数=12
  DEBUG LlmSubtitleTranslator : 字幕翻译批次重试用尽，整批回退原文: 序号=3, 句数=4
  全程 51 次 Connection refused / 34 次 ResourceAccessException / 17 次 Retry error；
  三个批次全部回退原文，整份产物 0% 被翻译。
  （run 6 总耗时约 210 秒，正是 C46 记的「单次最坏 6–9 分钟」量级。）

【这是有意的兜底，但兜底的「可观测」没落地】
  LlmSubtitleTranslator 的类注释原话：
    「全败整批回退原文（宁可没译，不可乱译），并把回退的段数计进 TranslateResult#untranslatedCount()」
    代码内注释原话：
    「静默产出未翻译的行是本条最需要防的事，所以让它可观测（调用方能看到 untranslatedCount）」

  但实际的可观测面只有两处，都不构成「用户/运维能看见」：
    1. SubtitleTranslationCoordinator:163 一行 **log.debug**（"…retry={}, untranslated={}"）
       —— 生产日志级别是 root INFO，debug 不输出；只有本机 com.vidsage=DEBUG 才看得见。
    2. TranslatedSubtitle 上的 untranslatedCount 字段 **没有任何读取方**
       （grep "untranslatedCount()" 全仓只命中：LlmSubtitleTranslator 写、Coordinator 读一次塞进 log，
         以及两处 record 定义本身）。
  => 用户可见面全部是成功信号：run SUCCEEDED / artifact READY / error_message NULL /
     /artifacts 里 TRANSLATED(zh-Hant) 正常列出并可供下载。

【归属】
  **不是本次重构引入的**：LlmSubtitleTranslator 的兜底逻辑早于本任务
  （该文件历史可追到 2026-10-07 之前；本次 8 段未改这段语义）。
  本次重构反而让它更容易发生被忽略 —— 新模型把「产物权威」搬到 DB，
  而这一行产物在 DB 里长得和一条正常译文**完全一样**（READY / 有文件 / 有 sha256）。

【定性】真缺陷（静默错交付），但**不在父任务 AC1–AC9 的字面范围内**，本轮不修。
  建议：见 implement.md §8 发现表 F1。

4. 附带确认到的两条正确行为
================================================================

(a) 同语种复用不发 LLM：run 5（TRANSLATE → en）在 LLM 完全不可用时仍 **SUCCEEDED**，
    且是秒级完成 —— 因为 en 已有 READY 译文，命中复用，压根没调 LLM。
    这正是 S5/S6.5 定的「再翻同语种不发 LLM」，在断网条件下得到了一次意外但有力的旁证。

(b) 启动收口在空库上不误伤：Updates: 0（见 §0）。
