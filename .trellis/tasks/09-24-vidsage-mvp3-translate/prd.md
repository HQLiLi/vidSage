6. 导出双语 SRT（一条时间轴，上行原文、下行译文）。
7. 翻译阶段产物落盘、断点复用。

## 不做

1. ~~反思/重写轮次的完整实现（本期只留接口）~~ → **连接口也不留**（2026-09-28 拍板）。
   理由：反思轮本质是「拿第一遍译文再发一次 LLM 往返」，天然可加。预留一个今天走不到的分支，
   与项目已两次拍板的取向冲突（`speakerId` 不预留恒为 null 的槽位、`LLMProvider` 接口不建）。
   design 里写清「下一轮挂在哪」即可。
2. **双语 SRT 的形态变体**（一条两行以外的排布）：本期按最常规形态落地，2026-09-28 拍板先挂起；
   形态要改时只动渲染器。
3. **异步管线 / SSE 收编**：翻译与清洗同形，走同步端点。长视频逐批往返会跑很久、可能顶到
   HTTP 客户端超时，这是已知限制（同 `SubtitleController` 类注释所述的临时面），等 MVP-1 落地时一并收编。
4. **相似度守卫的去留**：本期只加观测、不改行为。是否删除或重新定阈值，等真实素材的数据
   （见「观测项」与 design §九）。
5. 翻译器与清洗器的骨架合并（抽公共基类）：本期两个类各自独立，等第 4 条定案后再说。

## 观测项

这两项是本期交付的一部分，不是可选项——它们是两个悬置决策的取证手段：

1. **清洗批次的字数**：现行批次 DEBUG 日志记了句数、没记字数，导致无法判断
   `batch-size` 与 `max-batch-chars` 到底哪个判据实际生效。补上字数后跑一条真实素材即可定位。
2. **清洗校验失败的分类**：`validate` 失败分「键集不一致」与「改动过大」两类，现在合并计数，
   无法回答相似度守卫有没有拦下过东西。分开计数（不改行为）。
   分类必须是结构化的，不靠字符串前缀——文案一改就会静默失效，而它服务的正是「观测」这件事本身。

## 验收标准

- [ ] 输入一份已清洗字幕（`-clean.json`），产出双语 SRT；条数与起止时间与输入逐条一致（时间轴对齐）。
- [ ] 译文使用目标语种；术语表内的专有名词在译文中保留原文写法（抽查验证）。
- [ ] 同一术语/称谓全片译法一致（抽查验证）。
- [ ] 源语种 == 目标语种时：不调用 LLM，产物仍完整落盘，响应带明确标记。
- [ ] 上下文落盘 `context-<route>.json`；清洗跑完后再跑翻译，翻译**不重复调用摘要**。
- [ ] 摘要失败时不落盘（不得写出空上下文缓存），翻译照常进行。
- [ ] 断点复用：产物已存在时重跑不调用 LLM，各项统计归零。
- [ ] `-clean` 缺失时报错信息指明「缺哪个文件、先跑哪一步」。
- [ ] 观测项落地并有一条真实素材的读数（批次句数/字数分布、校验失败分类计数）。
- [ ] 至少一条真实运行证据（learning-records）。
